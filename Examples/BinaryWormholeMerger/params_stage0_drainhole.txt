# BinaryWormholeMerger -- Stage 0.6: does the REGULAR throat survive refinement?
# (research/merger/Plan.md, implementation plan Stage 0.)
#
# This is a t = 0 probe, not a physics run.  It exists to answer the one
# question that killed the previous geometry: put a wormhole throat in the
# initial data, refine the grid, and is the throat still there?
#
# With the Brill-Lindquist puncture throat the answer was NO.  Measured
# 2026-08-28 on identical data (research/merger/Plan.md, "Route B traps"): the throat was
# present at max_level = 0 and GONE at max_level 1 and 2, because the solved
# data arrived as a file at level-0 resolution and prolongation filled the
# puncture interior with a nearly constant chi.  R then rose monotonically from
# the centre and there was no interior minimum before the first step.
#
# Two things change here.  The throat is a regular drainhole, so chi at the
# minimal surface is 0.173 rather than ~1/16 and falling; and the data is
# ANALYTIC, so BinaryWormholeLevel::initData evaluates it at each level's own
# dx instead of interpolating a level-0 file.  Both are needed: the analytic
# route alone would still have put a puncture on the grid.
#
# Configuration: one throat, a = 2, m = 1 (M_ADM = 1), so
#   minimal surface   rbar = (m + sqrt(m^2+a^2))/2 = 1.618
#   areal radius      R_min = e^{-u(m)} sqrt(m^2+a^2) = 3.890
#   chi at the throat = 0.173  ->  proper cell width 2.40 dx
# all three predicted in closed form by
# grteclyn-wrapper/scripts/validation/drainhole_throat_check.py.  The run passes
# if the measured R_min lands on 3.890 at max_level 0, 1 AND 2, and sharpens
# rather than vanishing as dx falls.
#
# Launch through the campaign launcher, never directly:
#   WHM_PARAMS=params_stage0_drainhole.txt WHM_CONSUME=0 WHM_MAX_LEVEL=0 \
#     bash grteclyn-wrapper/scripts/campaigns/wormhole_merger/run_single.sh
# then repeat with WHM_MAX_LEVEL=1 and 2 (WHM_NAME keeps them apart).
# The three path keys below are placeholders the launcher rewrites.
