## The merger campaign: where to look

| I want to… | go to |
|---|---|
| know what is running, queued, decided | [`research/merger/STATUS.md`](research/merger/STATUS.md) — one page, current only |
| know why (the diary, every decision) | [`research/merger/GPU_PLAN.md`](research/merger/GPU_PLAN.md) — long; search by dated heading |
| decode a run name, a stream column, a sign, "MOTS" | [`research/merger/GLOSSARY.md`](research/merger/GLOSSARY.md) |
| read or check the paper | [`research/merger/article/research.tex`](research/merger/article/research.tex); its numbers come from [`article/claims/`](research/merger/article/claims/README.md) via the generated `article/numbers.tex` |
| see what a run is for | [`results/merger/runs_registry.tsv`](results/merger/runs_registry.tsv) (prose, by hand) |
| see what a run actually ran (binary, seeds, name check) | [`results/merger/runs_index.tsv`](results/merger/runs_index.tsv) (generated by `analysis/run_index.py`) |
| know which binary is which | [`results/merger/binaries.tsv`](results/merger/binaries.tsv); the files are in `runs/wormhole_merger/bin/` |
| launch a run | [`grteclyn-wrapper/scripts/campaigns/wormhole_merger/launch.sh`](grteclyn-wrapper/scripts/campaigns/wormhole_merger/launch.sh) → `run_single.sh` → `preflight.py`, `run_manifest.py` |
| build a binary | [`…/wormhole_merger/build_binary.sh`](grteclyn-wrapper/scripts/campaigns/wormhole_merger/build_binary.sh) (source: `Examples/BinaryWormholeMerger/`) |
| find a template | `runs/wormhole_merger/templates_scan/params_*.txt` (untracked; each packed run keeps its own copy as `evolution_params.txt`) |
| find raw output | `runs/wormhole_merger/<NN_group>/[<sub>/]<run>/` — `params.txt`, `run.log`, `run_manifest.json`, `data/*.dat`, `small_data/`, `frames/` |
| find plotfiles / checkpoints | `/tmp/grteclyn_scratch/<run>/` on the GPU node that ran it — node-local, pruned by hand (`runs/wormhole_merger/MANIFEST_CLEANUP_*.md`) |
| find packed results | `results/merger/campaign/<group>/[<sub>/]<run>/` — thinned streams, `evolution_params.txt`, `run_manifest.json`; resolve runs by name with `results/merger/analysis/pack_paths.py` |
| run an analysis | `results/merger/analysis/*.py` (numpy only; read the pack) |
| find a figure / its script | [`results/merger/figures/FIGURES.md`](results/merger/figures/FIGURES.md); scripts in `grteclyn-wrapper/src/grteclyn_wrapper/visualisation/wormhole_merger/plot_*.py` |
| close out a finished run | `research/merger/closeout.sh <run>` → `file_run.sh` → `research/merger/pack_results.sh` |
| movies, GW search | `results/merger/movies/`, `results/merger/gw_search/` (strain cache in `runs/gw_search/`) |

The campaign's code lives in four places by design: the launcher in
`grteclyn-wrapper/scripts/campaigns/wormhole_merger/`, figures in the wrapper's
`visualisation/wormhole_merger/`, pack analysis in `results/merger/analysis/`
(so a copy of the pack stays runnable), closeout and packing in `research/merger/`.

## How to

```bash
# Python: the wrapper's venv (set up once: cd grteclyn-wrapper && uv sync --extra plots --extra visualization --extra gw-search)
PY=grteclyn-wrapper/.venv/bin/python

# redraw a figure (reads the pack, writes results/merger/figures/<group>/)
$PY -m grteclyn_wrapper.visualisation.wormhole_merger.plot_horizon_regrowth

# check every number the paper quotes against the pack; regenerate numbers.tex
(cd research/merger/article && ../../../$PY claims/claims.py check && ../../../$PY claims/claims.py tex)

# will this template run as written on this binary?  (seconds, launches nothing)
bash grteclyn-wrapper/scripts/campaigns/wormhole_merger/launch.sh --template <params> \
     --name <run> --gpu <id> --profile none --preflight-only --binary <bin>

# build a binary named by, and stamped with, its commit (records results/merger/binaries.tsv)
bash grteclyn-wrapper/scripts/campaigns/wormhole_merger/build_binary.sh --tag <word>

# rebuild the run index (also part of pack_results.sh)
$PY results/merger/analysis/run_index.py results/merger
```

## Not here

- **No LaTeX engine** on the GPU nodes: the article compiles elsewhere.
- **`runs/` is not in git** (templates included): what must survive is packed into `results/`.
- **Scratch is per node.** The second GPU node's `/tmp` is invisible from the first;
  node labels ("first/second GPU node") map to hosts only in the local, untracked
  `runs/wormhole_merger/NODES.local.md`.
